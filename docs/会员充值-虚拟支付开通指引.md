# 会员充值 · 微信「虚拟支付」开通指引

> 代码已经写好了（`backend/src/pay/`），现在卡在**资质**这一环。下面是要你做的事，做完把 3 个参数发我，我配上去就能收款。

---

## 一、先搞清楚一件事：不能用普通微信支付

会员、AI 生成额度、章节解锁，在微信眼里都算**虚拟商品**。

微信 2026-02-27 发布《小程序虚拟支付业务管理规范更新公告》：**自 2026-04-01 起，售卖虚拟商品的小程序必须全终端接入官方「虚拟支付」接口**（`wx.requestVirtualPayment`）。继续用普通商户号收虚拟商品的钱属违规，会被限制功能乃至终止服务。

iOS 端更严格——虚拟商品的钱必须走苹果 IAP。虚拟支付已经帮你打通了这条路。

| 终端 | 费率 | 结算 |
|---|---|---|
| Android 等 | 1%（腾讯技术服务费） | T+3 |
| iOS | 12%（Apple 佣金） | 约 45-60 天 |

## 二、开通条件（先自查）

- [ ] 小程序已完成**微信认证**（你的已认证，有效期至 2027-10-23 ✓）
- [ ] 已完成**小程序备案**（你的已备案，2025-08-12 通过 ✓）
- [ ] 主体类型：个人 / 个体工商户 / 企业均可
  - **个人主体**：需持中国大陆居民身份证，**服务类目需含「工具」**，月支付限额 10 万元
  - **企业 / 个体户**：可申请普通微信支付商户号，也可走虚拟支付

⚠️ **这里有个要确认的点**：你现在的主营类目是「深度合成 > AI创作」。
个人主体开通虚拟支付要求类目含「工具」。**如果你的主体是个人，需要额外加一个「工具」类目**，否则申请会被卡。企业/个体户主体没有这条限制。

---

## 三、开通步骤（后台操作，约 10 分钟）

1. 登录 **mp.weixin.qq.com**
2. 左侧栏 → **支付与交易 → 虚拟支付**
3. 点「开通」→ 勾选协议 → 填资料（个人身份信息 / 提现账户 / 支付管理员）
4. 提交后等审核（个人主体一般 5 分钟内）
5. 刷新页面确认审核通过 → **扫码签约**
6. 进入**道具管理**，创建一个道具（这就是你卖的商品）：
   - 道具名称：例如 `VIP月卡`
   - 价格：**99 元**（要和代码里的价格对上，否则下单报错）
   - 记下**道具 ID**（如 `vip_month`）
   - **点「发布」**（不发布用不了）
7. **基本配置**里抄下这两个：
   - **OfferID**（你的支付账号）
   - **现网 AppKey**（支付密钥）

> iOS 端还要配置**小程序简称**（Apple 支付要展示 display name）：
> mp 后台 → 左下角头像 → 账号设置 → 基本信息 → 小程序简称。
> 配置后回「虚拟支付 → 基本配置」开通苹果 IAP 支付。

## 四、把 3 个参数发我

拿到后把这三项发我（我配到服务器 `.env` 并重启）：

```
VP_OFFER_ID=你的 OfferID
VP_APP_KEY=你的现网 AppKey
VP_PRODUCT_VIP_MONTH=你的道具ID
```

可选（改价格时用，默认 9900 分 = 99 元）：

```
VP_PRICE_VIP_MONTH=9900
```

另外建议设一个管理密钥，用于「人工开通」（支付没配好时给熟人开会员）：

```
ADMIN_KEY=你自己起一个长随机串
```

## 五、还要在后台配一个回调地址

支付成功后微信要通知我们的服务器发货，否则用户付了钱却没开通。

mp 后台 → **开发与服务 → 开发管理 → 消息推送** → 添加：

- URL：`http://120.79.174.44:3001/pay/notify`
- 消息类型：选 **event / 事件推送**

> 添加时微信会先请求这个 URL 做校验（会回 `echostr`），接口已经写好了，能直接通过。

## 六、代码里已经做好的安全约束

这几条是钱的事，说明一下为什么这么写：

1. **发货依据是官方查单，不是推送**
   任何人都能往回调 URL POST 一段假 XML。所以收到推送后只当"去查一下"的信号，
   必须调官方 `query_order` 确认真的收了钱才开通会员。伪造推送拿不到任何东西。

2. **session_key 加密落库**
   下单需要用它做用户态签名。以前登录时拿到就丢了，导致根本付不了款。
   现在用 AES-256-GCM 加密存储，不进日志、不出任何接口。

3. **幂等**
   同一笔订单微信可能推 15 次，以平台单号去重，不会重复加时长。

4. **未配置就明说缺什么**
   `/pay/goods` 会返回 `enabled:false` 并列出缺哪几项，绝不假装有支付。

5. **iOS 版本校验**
   iOS 端要求微信 ≥ 8.0.68，不够会提前提示更新，避免付了款才发现付不了。

---

## 七、上线前必须做的一件事

**用一笔小额真单完整走一遍**：支付 → 收到推送 → 会员开通 → 后台账单金额一致。

官方检查清单里明确要求这一步。虚拟支付的字段在不同版本叫法有差异，
我的"已支付"判据取了三个字段里的任一个（`paid` / `pay_time` / `transaction_id`），
真跑一笔才能确认你的账号下实际返回的是哪个。

## 八、过渡方案：先人工开会员

支付还没开通前，你也能给具体的人开会员（比如给朋友、给测试号）：

```
POST http://120.79.174.44:3001/pay/manual
{ "openid": "对方的openid", "months": 1, "adminKey": "你设的ADMIN_KEY" }
```

对方的 openid 可以在「我的」页看到（脱敏显示后 4 位），完整值要我查库给你。
