## 6. 本地 Markdown → Word 的正确姿势（editor_sdk）

用 `tencent-local-office-edit` 技能的三步，**不要**用 doc_ 工具逐段插入：

```bash
cd "<skills>/tencent-local-office-edit"
PY="C:/Users/53430/.workbuddy/binaries/python/versions/3.13.12/python.exe"
# 1) 建空文档，拿 file_id
"$PY" edsdk.py call create_doc
# 2) 整篇导入 —— markdown 参数支持 "file://<绝对路径>"，避免把长文塞进命令行
"$PY" edsdk.py call doc_insert_markdown file_id=<id> idx=0 "markdown=file://C:/path/xxx.md"
# 3) 另存到目标路径
"$PY" edsdk.py call save_file file_id=<id> "file_path=C:/path/xxx.docx"
```

**要点/坑**：
- `doc_insert_markdown` 的 `markdown` 字段可传 `file://<绝对路径>` 直接读文件，**长文必用**（否则命令行爆)
- 转出来的标题**不用命名样式**，走 `<w:outlineLvl>` + 直接格式 → 导航窗格和大纲正常，
  但 `pStyle` 数量为 0，**不要用 pStyle 判断标题是否成功**，要查 `outlineLvl`
- 校验 docx 内容：`zipfile` 读 `word/document.xml`，正则抽 `<w:t>` 拼段落 + 数 `<w:tbl>`
- 保存后**不要**调 `close_file`，会关掉用户正在看的预览
- `doc_to_image` 会把文件上传到腾讯 COS 再转图 —— 内部/草稿文件慎用，不如直接 `present_files` 让作者自己看
- 路径含中文没问题（本例 `小说小程序/docs/隐私政策.docx` 一切正常）

## 13. 已加 NovelWatchdog 每分钟守护任务（2026-10-06 12:5x）

- 脚本 `deploy/watchdog.cmd`（**必须 CRLF**，LF 有静默失败风险——Write 工具默认写 LF，写完要转换）。
  逻辑：`pause.lock` 存在→跳过（不跟部署抢）；3001 没监听→等 10s 复查（避免误判 node 正在 5 秒自愈）→仍无→`schtasks /run /tn NovelBackend`，写 `watchdog.log`。
- 创建：`schtasks /create /tn NovelWatchdog /tr "C:/erp/novel-backend/watchdog.cmd" /sc minute /mo 1 /f`
- **端到端实测通过**：`schtasks /end /tn NovelBackend` + 杀 node（真·连循环一起死，模拟 10-02 那次故障）→
  端口确认 DOWN → 95 秒后自动恢复，`watchdog.log` 有 "WATCHDOG: 3001 down, starting NovelBackend" + "成功: 尝试运行"。
- **坑1**：这台机器 **没有 wmic**（`wmic` 不是内部命令），拿父进程 PID 失败。
  改用 `schtasks /end /tn <任务名>` 精确终止循环，比杀进程安全（不会误伤同机器上的 ERP 测试服）。
- **坑2**：`timeout /t` 在 ssh 无 stdin 下报「不支持输入重新定向」，延时一律用 `ping -n N 127.0.0.1 >nul`。
- **坑3**：`tasklist /v` 的窗口标题全是「暂缺」，无法据此定位是哪个 cmd；别用 `taskkill /IM cmd.exe` 粗暴杀（会误杀 ERP）。
- 注意：NovelWatchdog 的登录状态是「只使用交互方式」（ssh 创建没法带密码），与主任务 NovelBackend 的「交互/后台」
  不同；服务器无人登录时守护可能不跑——但目前表现正常，先观察。
