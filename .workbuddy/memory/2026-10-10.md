# ② 作品页改版 + 开书自动黄金三章 + 修「小程序封面还是土的」

## 真因：云函数一直是旧版（不是画得不好）
- 现象：小程序上封面仍是 canvas 那张扁平矢量图；后端 `POST /novel/:id/cover-image` 报错。
- 链路：`ai.image()` **只能走云函数**（云开发赠送生图额度仅认小程序端/云函数来源），
  地址 `CLOUDBASE_FN_URL=https://zhicheng-novel-d9g7rdxjo798da6d0-149926353851.ap-shanghai.app.tcloudbase.com/ai-write`。
- 探活证据：POST `{kind:'image'}` 竟返回 `{"text":"你好呀，我是混元…"}` —— **旧版函数把出图请求当写文**。
- 根因：改了 `backend/cloudfunctions/ai-write/index.js` 但**从未部署**。后端 tarball 不含云函数，改了不生效。

## 云函数部署（新踩通，已写进 skill `novel-miniprogram-release`）
```
cli.bat cloud functions deploy --env zhicheng-novel-d9g7rdxjo798da6d0 \
  --paths ".../backend/cloudfunctions/ai-write" --project "<项目根>" --port 43743
```
- 需要微信开发者工具**已登录 + 服务端口已开**；`cli islogin` 会报出端口。
- 教训：`HTTP/1.1 443 Unknown` + `x-cloudbase-upstream-type: Tencent-SCF_HTTP` +
  `x-cloudbase-upstream-status-code: 443` = 云函数状态码表里的 **443 UserCodeError**；
  **大概率只是函数在 `Updating`**，等 1-3 分钟重试即可。当时误判成"依赖/启动坏了"，多花了时间。
  另：`Updating` 期间再发部署会报 `当前函数处于Updating状态，无法进行此操作`。
- 部署后验证四连（`backend/scripts/probe-image.mjs`，只读 .env 不打印 token）：
  GET 200 / 出文 200 / **错口令 401（证明 AI_WRITE_TOKEN 没被冲掉）** / 出图 200 返回 cos URL。
- `cli cloud functions download` 能把线上包拉回来比对，立刻区分"没传上去"vs"传上去起不来"。

## 开书自动出黄金三章
- `startQuickJob` 任务链补齐：**定位 → 大纲 → 全书脉络+时间线 → 上架资料 → 黄金1-3章 → 封面**。
- `generateChapter(id, dto, {skipQuota})`：开书那三章**不占当日日更额度**
  （否则"新建小说自动出黄金三章"第二本就悄悄失效，作者只看到 1 章）。
- 新增 `dailyNewNovels=1` + `checkNewNovelPerDay`（三档统一）：
  开一本书会一次性消耗大纲/脉络/时间线/黄金三章，不设限就能删了重开绕过日更额度。
  **`autoCreated=true`（被拒重开）不占这个名额** —— 拒稿重开是核心闭环，不能卡。
  实测：同身份开第二本 → 400 并给出人话提示。
- **踩坑**：首次全链路跑到 golden 步失败 —— `云函数返回异常 500: 该 API key 已达到该模型每分钟请求数(QPM)上限`。
  一次开书就是七八次模型调用，**QPM 限流是必然不是异常**。
  修：`cloudbase.service` 加 `callFn`，识别限流/网络抖动 → 15s/30s/60s 退避重试；
  另在黄金三章之间加 6s 主动错峰。
  （不修的话这个功能就是"看运气"。）
